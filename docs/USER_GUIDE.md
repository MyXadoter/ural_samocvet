# Руководство диспетчера

[Документация](README.md) · [Запуск](LOCAL_SETUP.md) · [Форматы файлов](DATA_FORMATS.md)

## 1. Подготовить смену

После открытия страницы загружаются 10 демонстрационных заявок и 6 инженеров. Исходный план строится с начала смены, хотя в шапке установлено `14:30`.

Откройте «Настроить параметры смены». Здесь можно заменить заявки, загрузить инженеров, скачать нормативы, включить автопересчёт и задать текущее время. Для утренней демонстрации установите `08:00`, закройте настройки и нажмите «Рассчитать план».

Значения времени и автотриггера меняются непосредственно при работе с полями; кнопка «Сохранить параметры» закрывает диалог. Кнопка закрытия не откатывает уже изменённые параметры. Успешный импорт сразу заменяет набор и запускает утренний расчёт.

Для демонстрации собственных данных сначала подготовьте инженеров и заявки по [описанию форматов](DATA_FORMATS.md), затем загрузите оба файла и дождитесь расчёта. В отчёте проверяйте число принятых и отклонённых строк. Он относится к последнему загруженному файлу.

## 2. Прочитать результат

Над таблицей `Baseline → regret‑2` указан источник расстояний: OSRM либо резервная географическая оценка. Цифры зависят от входных данных, режима и доступности дорожного сервиса.

| Элемент | Что открывается или показывается |
|---|---|
| «Распределено» | Все назначенные заявки с временем и исполнителями |
| «Инженеры в плане» | Список сотрудников, статусы и переход к планам |
| «Общий пробег» | Расстояния по инженерам |
| «Свободный ресурс» | Матрица занятости по часам |
| «Перегружено» | Маршруты с временными наложениями |
| «Новые заявки» | Добавленные в текущей вкладке заявки |
| «Не распределено» / «Разобрать» | Заявки без назначения и форма разбора |

Свободный ресурс рассчитывается по полной длительности смен, а не только по времени, оставшемуся после текущего часа. Значок свободного часа в матрице не учитывает переезды. Подробные формулы — в [описании метрик](ALGORITHMS.md).

## 3. Открыть маршрут

Нажмите карточку инженера или «Открыть план». В плане показаны интервал работ, адрес, навык, объяснение назначения, статус и кнопка «Факт». Объяснение ближайшей альтернативы — справочная подсказка, а не доказательство того, что у альтернативного инженера есть свободное окно.

На карте номера показывают последовательность визитов, тёмная стартовая точка — начало маршрута. «Показать все» подбирает масштаб. Фильтры «Все», «С риском», «В резерве» одновременно меняют список и карту.

Линии могут идти по дорогам, но точки заявок учебные: адреса не геокодируются. При недоступности дорожного сервиса остаётся пунктир между точками. Блок «Требует внимания» содержит фиксированные демонстрационные сообщения и не является журналом текущих событий.

## 4. Зафиксировать исполнение

В плане инженера нажмите «Факт», выберите статус и задайте время:

| Статус | Поведение при оперативном пересчёте |
|---|---|
| «Не начата» | Разрешено новое назначение и изменение времени |
| «В пути» | Сохраняются инженер и плановый интервал |
| «Начата» | Сохраняются инженер и плановый интервал |
| «Завершена» | Сохраняются инженер и плановый интервал; факт окончания участвует в расчёте отставания |

Само наступление планового времени не фиксирует заявку. Установите фактический статус явно. Для завершённой заявки отставание считается как фактическое окончание минус плановое; фактическое время пока не сдвигает начало следующей работы автоматически.

## 5. Пересчитать будущее

«Перепланировать» всегда запускает оперативный режим. «Рассчитать план» выбирает режим по текущему времени: для стандартной смены в `08:00` — утренний, позже — оперативный. Точное правило для нестандартного начала смены приведено в [алгоритмах](ALGORITHMS.md).

При оперативном расчёте сохраняются назначения со статусами «в пути», «начата» и «завершена» из текущего плана. Остальные заявки могут сменить исполнителя и время. Возврат к утреннему расчёту не предназначен для сохранения фактов текущего дня.

Автопересчёт проверяет **строгое превышение** порога: при пороге 20 минут значение 20 не запускает его, 21 запускает. Проверка выполняется после изменения факта, включения автотриггера и изменения порога. Часы эмулируются вручную; фонового таймера хода смены нет. Вводите порог в указанном диапазоне 1–180 минут.

## 6. Внести событие

Для аварии выберите «Новое событие» → «Новая аварийная заявка». Заполните уникальный номер, адрес, район, окно, навык и транспорт. Длительность аварии — 100 минут. Нажмите «Внести и перепланировать»; заявка появится среди новых, будущая часть плана будет пересчитана.

Полная проверка импортируемых строк к этой форме не применяется. Самостоятельно проверьте, что конец окна позже начала и в нём помещается работа.

Для изменения доступности выберите «Новое событие» → «Статус инженера». Выберите сотрудника и нажмите «Снять с линии и перепланировать» либо «Вернуть на линию и перепланировать». Фактически закреплённые работы остаются у прежнего исполнителя, даже если он снят с линии; будущие перераспределяются.

## 7. Ручная корректировка

В плане инженера откройте «Ручное перепланирование», выберите незакреплённую заявку, инженера и начало работы. Форма проверяет доступность, навык, транспорт, окно и смену. Закреплённые заявки не предлагаются для переноса.

Если найдено временное наложение, выберите другое время либо включите «Разрешить только временное наложение» и укажите причину длиной не менее пяти символов. Причина сохраняется в памяти вкладки. Ошибки навыка, транспорта, окна или смены этим флажком не разрешаются.

Эта форма не проверяет физическую достижимость клиента с учётом дороги и не пересчитывает полный пробег после изменения. Прогноз изменения пробега в диалоге приблизительный. Для повторного автоматического расчёта нажмите «Перепланировать»; незакреплённое ручное назначение при этом может измениться.

Форма «Не распределено» → «Разобрать» использует упрощённый путь назначения. Она не выполняет полный набор проверок дороги, окна и окончания смены, а кнопка «Применить и пересчитать» фактически добавляет назначения без общего пересчёта. Для демонстрации контроля ограничений используйте диалог «Ручное перепланирование».

## 8. Сценарий демонстрации

1. Откройте свежую страницу, дождитесь окончательного статуса матрицы.
2. Покажите число заявок, инженеров, baseline и итоговый план.
3. Откройте одного инженера и объяснение назначения.
4. Покажите фактические статусы и действие «Перепланировать».
5. На свежем демо нажмите «Сценарий защиты»: время станет `12:20`, инженер `e5` будет снят с линии, добавится авария `P1`, появится окно «До → событие → после».
6. Покажите результат назначения `P1` и KPI; если она не назначена, объясните ограничение, а не обещайте гарантированный успех.

«Сценарий защиты» изменяет текущие данные и не откатывает их при закрытии окна. Запускайте его на исходном демо: он зависит от наличия определённого инженера или навыка FTTB. Для повторяемого показа обновите страницу. Особенности фиксации внутри этого сценария описаны в [ограничениях](VALIDATION.md).

## Завершение работы

Постоянного сохранения и экспорта плана нет. Обновление или закрытие страницы удаляет импортированные данные и изменения из текущей сессии. Для нового показа повторно загрузите исходные файлы. Локальный HTTP-сервер останавливается через `Ctrl+C` в терминале.
