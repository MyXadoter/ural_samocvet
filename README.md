Уральские самоцветы — помощник диспетчера
Прототип для кейса «Билайн Бизнес»: распределение заявок выездным инженерам с учётом навыков, транспорта, временных окон и смен.

Релиз: v0.1.0. Пошаговый локальный запуск на macOS, Linux и Windows · Описание релиза.

Текущее состояние
Работает веб-прототип: карта маршрутов, расписание, объяснения, реестр заявок, справочник инженеров, сравнение алгоритмов и добавление срочной заявки с автоматическим пересчётом будущего. Исходные 66 заявок «Востока» доступны отдельно для просмотра и поиска. Маршруты пока строятся на явно обозначенном учебном наборе: геокодирование исходных адресов и OR-Tools ещё не реализованы.

Открыть приложение
На подготовленном компьютере запустите ./start.command из корня проекта или откройте файл двойным щелчком. Он запускает сервер в фоне, проверяет готовность и открывает http://127.0.0.1:8000. Окно запуска можно закрыть. Повторный запуск открывает уже работающий сервер. Для остановки — ./stop.command; план останется на диске.

Не открывайте frontend/index.html как сайт: исходному React-приложению нужен сервер. При открытии HTML напрямую теперь показывается инструкция со ссылкой на рабочий адрес. Если страница не открывается, запустите start.command; сведения об ошибке будут в output/server.log.

Для первого запуска из исходников на другом компьютере нужны Python 3.11+ (проверено на 3.13), Node.js 22+ и pnpm 11.19.0. Сначала скачайте и распакуйте исходники репозитория или клонируйте его, затем откройте терминал в папке с этим README. В macOS/Linux:

npm install --global pnpm@11.19.0
python3 -m venv .venv
.venv/bin/python -m pip install -c constraints.txt -e '.[api]'
pnpm --dir frontend install --frozen-lockfile
pnpm --dir frontend build
bash start.command
Откройте http://127.0.0.1:8000. Ключ Яндекс Карт необязателен: без него работает OpenStreetMap. Для Windows и архива релиза с готовым интерфейсом см. LOCAL_SETUP.md.

Собранный интерфейс раздаётся самим FastAPI. Для изменения frontend: запустите API, затем pnpm --dir frontend dev; Vite проксирует /api на порт 8000. После изменений для обычного запуска выполните bash scripts/build_frontend.sh.

Демонстрация
Откройте «Планирование»: 13 учебных заявок, включая один заведомо невыполнимый визит.
Переключите «Базовый» / «Улучшенный», выберите инженера и остановку, прочитайте объяснение.
Откройте «Сравнение»: отображаются число назначений, инженеры, общий километраж и расстояние каждого инженера.
Нажмите «Срочная заявка», оставьте учебные значения по умолчанию и отправьте форму. Событие происходит в 12:00. План пересчитывается автоматически.
Нажмите «Что изменилось»: сравните назначения, время и порядок. Уже завершённые/начатые выезды сохранены.
В разделе «Исходные данные» покажите импорт и поиск по 66 строкам организаторов — они не подменены учебными точками.
На начальном учебном наборе оба алгоритма назначают 12 из 13 заявок: baseline использует 6 инженеров и 13,279 км, эвристика — 4 инженеров и 15,075 км. Это компромисс между метриками, а не улучшение всех показателей. После события цифры рассчитываются заново.

Карта: Яндекс и OpenStreetMap
Интерактивная карта работает через JavaScript API 3.0: цветные маршруты, номера остановок, стартовые точки, неназначенные заявки, выбор заявки, фильтр инженера, масштаб и показ всех точек. Координаты в API передаются в порядке [долгота, широта].

Если ключ отсутствует, Яндекс отклоняет подключение или загрузка длится больше 6 секунд, автоматически открывается OpenStreetMap через Leaflet. Выбор заявки, фильтр инженера и управление масштабом работают в обоих вариантах. На экране загрузки также можно сразу выбрать OpenStreetMap. Для подложки требуется интернет.

Получите ключ JavaScript API в кабинете разработчика Яндекса.
Настройте ограничение HTTP Referer для адреса сайта (для локальной разработки — 127.0.0.1 и localhost, для публикации — домен сайта). JS API 3.0 требует заполненного ограничения. Новые настройки могут применяться до 15 минут.
Скопируйте .env.example в .env в корне проекта и заполните YANDEX_MAPS_API_KEY=ваш_ключ. Если .env уже есть, добавьте только эту строку.
Откройте сайт и нажмите «Включить Яндекс» на карте. Если заменили уже загруженный ключ, обновите страницу. Пересборка интерфейса и перезапуск сервера при смене ключа в .env не нужны.
Ключ также можно задать переменной окружения YANDEX_MAPS_API_KEY — она имеет приоритет над файлом. /api/maps/config отдаёт только публичный браузерный ключ, не остальные настройки. .env исключён из Git; API-ключ не вшивается в сборку. Браузерный ключ виден посетителям по устройству JS API: доступ ограничивается разрешёнными доменами в кабинете Яндекса. Файл .env нельзя публиковать как статический ресурс.

Подключение карты не включает геокодирование CSV и дорожную матрицу времени — это отдельные этапы интеграции. Публичные тайлы OpenStreetMap используются с видимой атрибуцией, без массовой загрузки и офлайн-кеширования.

Быстрый запуск без установки зависимостей
Нужен Python 3.11 или новее. Команды выполнять из папки проекта.

python3 -m unittest discover -s tests -v
python3 -m dispatch.cli import 'Обезличивание/Восток Синтетические данные.csv' --output output/vostok.json
python3 -m dispatch.cli demo --output output/demo-comparison.json
vostok.json содержит 66 исходных заявок с демонстрационными длительностями и навыками, без координат. Эти заявки пока не готовы к расчёту маршрутов. Файлы организаторов не изменяются.

demo-comparison.json содержит сравнение двух алгоритмов на отдельном вымышленном наборе: 12 инженеров, 12 выполнимых заявок и одна заявка с заведомо невыполнимым окном. Его координаты не соответствуют адресам исходного CSV. Время в результате — целые минуты от начала дня, расстояния — километры.

API
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -c constraints.txt -e '.[api]'
python -m unittest discover -s tests -v

Документация: http://127.0.0.1:8000/docs.

GET /api/health — состояние сервиса.
GET /api/demo/compare — независимое сравнение начального демо.
POST /api/scenarios/demo — новая учебная сессия, данные и оба плана.
GET /api/scenarios/{id} — восстановление сохранённого дня, включая состояние после события.
POST /api/scenarios/{id}/urgent — срочная заявка и время события, автоматическое перепланирование. Версия защищает от повторного изменения устаревшего плана.
GET /api/source/vostok — импорт исходного CSV и отчёт о недостающих координатах.
Проверено на Python 3.13: 37 тестов, включая API, повторное перепланирование, сохранение начатых выездов, конфликт версий, ошибочный ввод и восстановление с диска. В constraints.txt сохранены проверенные версии Python-зависимостей, в frontend/pnpm-lock.yaml — frontend. Без API-зависимостей 11 проверок API пропускаются. Сборка TypeScript/Vite проходит. В браузере проверены полный сценарий срочной заявки, восстановление после обновления страницы, фильтр исходных данных, навигация, ошибка времени, Escape в диалоге и мобильная раскладка.

Правила расписания
Заявке требуется один навык; инженер должен им обладать.
Если указан обязательный транспорт, тип транспорта инженера должен совпасть.
Прибытие = завершение предыдущей работы + время переезда.
Начало = максимум времени прибытия и начала окна. Ожидание допустимо.
Начало работы должно попасть в окно, завершение — в смену.
Начальная позиция — стартовая точка инженера. Возвращение не требуется.
Все заявки должны относиться к одному дню и иметь уникальные ID.
Каждая заявка либо назначается один раз, либо получает причину неназначения.
Алгоритмы и метрики
baseline: порядок заявок и инженеров из входных данных; первая допустимая вставка в конец маршрута первого подходящего инженера. При отсутствии времени поступления порядок строк принимается за порядок поступления.

insertion_heuristic: сначала срочные заявки, затем ближайшее окончание окна; проверка каждого места вставки в маршруты с пересчётом всего расписания. Среди допустимых вариантов предпочтение уже занятому инженеру, затем меньшему приросту расстояния. Это локальная эвристика: она не гарантирует ни глобального оптимума, ни превосходства над baseline. Оба результата показываются отдельно.

Метрики: назначенные и неназначенные заявки, число инженеров с непустым маршрутом, расстояние каждого маршрута и суммарное расстояние. Сравнивать экономию нужно вместе с количеством выполненных заявок.

Данные и допущения
В исходных файлах Windows-1251 и разделитель ;; также поддерживается UTF-8.
Пустые строки пропускаются, строка адреса офиса читается отдельно.
Навыки и длительности задаёт демонстрационная таблица WORK_RULES в dispatch/importer.py. Их нужно согласовать с командой или организаторами.
Неизвестный тип работ, неверная дата, пустой адрес и повторный ID попадают в отчёт ошибок. CLI возвращает код 1, если есть ошибки строк.
Исходный набор не задаёт приоритет и транспортное ограничение: принимаются обычный приоритет и отсутствие ограничения.
Контрольное распределение не используется как вход утреннего планирования: в нём есть выполненные/отменённые работы, нужна отдельная политика статусов. Это также не замена обязательному baseline из ТЗ.
«Обезличивание 2» дублирует соответствующие файлы «Обезличивание»; импортировать обе папки вместе не нужно.
Расстояние оценивается по координатам, без дорожной сети. Скорость постоянная: авто 25, пешком 5, велосипед 15, общественный транспорт 18 км/ч. Время округляется вверх до целой минуты. Пробки, пересадки, парковка и дорожные препятствия не учитываются. Это демонстрационная оценка, не реальный дорожный пробег.
Нет оборудования, авторизации и БД. Для первого этапа они не требуются.
Сессии автоматически сохраняются в output/sessions/ атомарной записью. Идентификатор текущего дня хранится в sessionStorage вкладки. Обновление страницы и перезапуск сервера восстанавливают день. Кнопка «Новый день» создаёт отдельную сессию; старый файл не удаляется. В памяти держится до 100 сессий, остальные загружаются с диска по запросу. Прототип запускается одним процессом API. Обратный импорт JSON-экспорта пока не реализован.
Карта использует JavaScript API 3.0 Яндекс Карт с автоматическим переключением на OpenStreetMap при ошибке подключения. Пунктир показывает последовательность визитов, а не дорожный маршрут: расстояния и время переезда пока оцениваются по координатам, без пробок. Шрифт из Google Fonts имеет локальную системную замену.
Перепланирование
События должны идти в неубывающем порядке времени. Завершённые работы, визиты в процессе, начатые переезды и ожидание на объекте фиксируются. По принятому правилу инженер, уже выехавший к клиенту, завершает этот визит; перенаправление в пути пока не моделируется. Свободный инженер стартует с последней точки не раньше времени события. После завершения смены новые работы не назначаются.

Оба алгоритма после события получают один фактический префикс текущего улучшенного плана. Поэтому сравнение относится к решениям для одного состояния дня. Будущие заявки могут сменить время, порядок или исполнителя. Изменения отображаются отдельным списком, зафиксированные визиты — значком замка в расписании.
